1Ściąga: pytania, które już padły

Lista z czatu: tematy, o które pytano na zaliczeniu. Najpierw spróbuj odpowiedzieć sam, potem rozwiń.

Co to jest przeładowanie funkcji (metody)?

Kilka metod o tej samej nazwie w jednej klasie, różniących się listą parametrów (liczbą, typem lub kolejnością). Sam typ zwracany nie wystarczy. Przykład: dodaj(int, int) i dodaj(double, double). Przeładowanie a nadpisanie

Czy metoda abstrakcyjna w klasie wymusza abstrakcyjność klasy?

Tak. W drugą stronę nie: klasa abstrakcyjna nie musi mieć żadnej metody abstrakcyjnej.

Jakim operatorem porównasz tożsamość obiektów?

Java, C#: == na referencjach (a equals() porównuje zawartość). Python: is. JavaScript, PHP: ===. Tożsamość a równość

Jakim symbolem w UML oznacza się kompozycję?

Linia ciągła z wypełnionym (czarnym) rombem po stronie całości. Pusty romb to agregacja. Wszystkie strzałki

Jak w UML zapisać metodę statyczną?

Podkreśleniem, np. + policz(x: int): int. Kursywa oznacza abstrakcyjność.

Wymień zasady SOLID

S jedna odpowiedzialność, O otwarte na rozszerzanie, zamknięte na modyfikację, L podstawienie Liskov, I segregacja interfejsów, D odwrócenie zależności. Tabela z przykładami

Pamiątka: co robi i jak ją narysować?

Zapisuje i przywraca stan (Cofnij) bez łamania hermetyzacji. Twórca tworzy i czyta Pamiątkę (przerywana ze strzałką), Opiekun przechowuje listę pamiątek (ciągła z pustym rombem). Diagram

Adapter: co robi i jak go narysować?

Tłumaczy jeden interfejs na inny. Adapter implementuje interfejs docelowy (przerywana z pustym trójkątem) i trzyma referencję do adaptowanego obiektu (ciągła ze strzałką). Diagram

x = r · cos α, y = r · sin α

Wzór: kartezjański (x, y) na biegunowy (r, α)

r = √(x² + y²), α = atan2(y, x). Matematycznie α = arctan(y / x) dla x > 0; dla x < 0 dodaj π (180°). Kalkulator

Klasa to definicja obiektów: określa ich tożsamość (jednoznaczna identyfikacja i przynależność do klasy), dopuszczalny stan (wartości pól) i zachowanie (metody). Obiekt to instancja klasy. Zbiór metod klasy to jej interfejs.

Hermetyzacja (enkapsulacja)

Wiąże dane z metodami, które na nich operują, i ukrywa stan przed bezpośrednim dostępem z zewnątrz. Dzięki niej obiekt nie zmieni stanu innego obiektu w nieoczekiwany sposób. Gdy do wszystkich pól dostaje się wyłącznie przez metody, to hermetyzacja pełna.

Tożsamość a równość

Pułapka: w Javie == na dwóch String z new daje false, chociaż tekst jest ten sam.

Tożsamość: dwie zmienne wskazują ten sam obiekt w pamięci. Równość: dwa różne obiekty mają tę samą zawartość.

String a = new String("ala");
String b = new String("ala");
a == b;        // false: dwa różne obiekty (tożsamość)
a.equals(b);   // true: ta sama zawartość (równość)
a == a;        // true

C#: == dla klas porównuje referencje, chyba że klasa przeciąża operator (jak string); pewne sprawdzenie tożsamości daje ReferenceEquals(a, b). C++: porównujesz adresy, &a == &b.

4Rodzaje metod

Metody dzieli się według tego, do czego należą (klasa czy obiekt) i jak zachowują się przy dziedziczeniu.

Instancyjna (zwykła)
Należy do obiektu, trzeba go najpierw utworzyć: auto.jedz(). Widzi pola i stan obiektu.
Statyczna static
Należy do klasy, wołasz ją bez obiektu: Math.sqrt(9). Nie widzi zwykłych pól obiektu. W UML: podkreślenie.
Abstrakcyjna abstract
Sama sygnatura, bez ciała. Tylko w klasie abstrakcyjnej; klasy pochodne muszą ją dopisać. W UML: kursywa.
Wirtualna virtual / nadpisana override
Ma domyślny kod w klasie bazowej, klasa pochodna może go zmienić. W Javie każda zwykła metoda jest domyślnie wirtualna.
Finalna final / zapieczętowana sealed
Zablokowana: klasa pochodna nie może jej nadpisać.

Pokaż wszystkie rodzaje w jednej klasie (Java) 
abstract class Figura {
    private static int licznik = 0;            // pole statyczne: jedno na całą klasę
    protected String nazwa;

    Figura(String nazwa) {                     // konstruktor
        this.nazwa = nazwa;
        licznik++;
    }
    static int ileFigur() { return licznik; }  // statyczna: Figura.ileFigur()
    abstract double pole();                    // abstrakcyjna: brak ciała
    String opis() { return nazwa + ": " + pole(); }  // instancyjna (wirtualna)
    final String id() { return nazwa.toUpperCase(); } // finalna
}

class Kolo extends Figura {
    private final double r;
    Kolo(double r) { super("koło"); this.r = r; }
    @Override
    double pole() { return Math.PI * r * r; }   // nadpisanie metody abstrakcyjnej
}

5Relacje i strzałki UML

Na diagramie klas wystarczą prostokąty i sześć rodzajów linii. Kolejność poniżej to kolejność według siły relacji z Lab 1, od najsilniejszej.

  1. Dziedziczenie

    Przekazanie wszystkich cech. Klasa pochodna jest szczególnym przypadkiem bazowej.

    Linia ciągła, pusty trójkąt przy klasie bazowej. Czasem z dopiskiem Extends.

  2. Implementacja interfejsu

    Klasa realizuje kontrakt interfejsu. Nie ma jej na liście z Lab 1, ale rysuje się ją w każdym wzorcu.

    Linia przerywana, pusty trójkąt przy interfejsie.

  3. Kompozycja (agregacja całkowita)

    Całość tworzy części i nimi zarządza. Żyją tyle samo: usunięcie domu usuwa pokoje.

    Linia ciągła, wypełniony romb przy całości.

  4. Agregacja częściowa

    Całość zawiera części, ale nimi nie zarządza. Po likwidacji firmy osoby dalej istnieją.

    Linia ciągła, pusty romb przy całości.

  5. Asocjacja

    Czasowe powiązanie niezależnych obiektów. Nikt nikogo nie tworzy ani nie usuwa. Zwykle ma nazwę-czasownik.

    Linia ciągła; otwarta strzałka, gdy chcesz pokazać kierunek „kto kogo wywołuje”.

  6. Zależność

    Jedna klasa oddziałuje na drugą, np. tworzy jej obiekt albo bierze go w parametrze.

    Linia przerywana z otwartą strzałką, często ze stereotypem «create».

Krotności nowe

Romb zawsze stoi przy całości, a trójkąt przy klasie ogólniejszej. Na odwrót to najczęstszy błąd.

Liczby przy końcach linii mówią, ile obiektów bierze udział w relacji: 1 dokładnie jeden, 0..1 zero lub jeden, 0..* lub * dowolnie wiele, 1..* co najmniej jeden, n dokładnie n. Na rysunku asocjacji: jedna osoba akceptuje od zera do n umów.

Singleton kreacyjny nowe

Ogranicza liczbę obiektów klasy do jednego i daje do niego globalny dostęp.

Trzy elementy: prywatny konstruktor, statyczne pole z instancją (na początku null) i statyczna metoda getInstance(), która zwraca instancję, a jeśli jej nie ma, wywołuje konstruktor i zapamiętuje wynik.

Pułapka: bez synchronized dwa wątki mogą naraz zobaczyć null i utworzyć dwa obiekty.
Kod (Java) 
public final class Konfiguracja {
    private static Konfiguracja instance = null;   // statyczne pole
    private Konfiguracja() { }                     // prywatny konstruktor

    public static synchronized Konfiguracja getInstance() {
        if (instance == null) {
            instance = new Konfiguracja();
        }
        return instance;
    }
}

Konfiguracja a = Konfiguracja.getInstance();
Konfiguracja b = Konfiguracja.getInstance();
// a == b  ->  true, to ten sam obiekt

Adapter strukturalny

Łączy dwie niepasujące klasy: tłumaczy interfejs, którego oczekuje klient, na interfejs istniejącej klasy, bez ruszania jej kodu.

Jak przejściówka do gniazdka albo nakładka, która z XML starej biblioteki robi JSON dla nowego systemu. Poniżej wersja z Lab 2: klient chce kąt wektora w układzie biegunowym, a Vector2D zna tylko x i y.

Jak narysować adapter: adapter implementuje interfejs docelowy (przerywana linia, pusty trójkąt) i trzyma referencję do obiektu adaptowanego (ciągła linia ze strzałką). Wszystkie metody poza nową deleguje do srcVector.

Lab 2 pokazuje też wersję z dziedziczeniem (2DPolarInheritance extends Vector2D). Wada: działa tylko przy kompilacji, nie zaadaptujesz istniejącego obiektu.
Kod (Java) 
interface IVector  { double abs(); double cdot(IVector p); double[] getComponents(); }
interface IPolar2D { double getAngle(); }

class Polar2DAdapter implements IVector, IPolar2D {
    private final Vector2D srcVector;
    Polar2DAdapter(Vector2D v) { this.srcVector = v; }

    public double abs()               { return srcVector.abs(); }        // delegacja
    public double cdot(IVector p)     { return srcVector.cdot(p); }
    public double[] getComponents()   { return srcVector.getComponents(); }

    public double getAngle() {                                           // jedyna nowa logika
        double[] c = srcVector.getComponents();
        return Math.atan2(c[1], c[0]);
    }
}

Dekorator strukturalny

Dynamicznie dokłada obiektowi nowe zachowanie, bez zmiany jego kodu i bez mnożenia podklas.

Zamiast klas KawaZMlekiem, KawaZSyropem, KawaZMlekiemISyropem owijasz KawaBaza w dekorator Mleko, a potem w Syrop. Każdy woła cena() obiektu w środku i dolicza swoją kwotę. W Lab 2 dekorator dodaje wektorowi trzeci wymiar i iloczyn wektorowy.

Jak rozpoznać dekorator na diagramie: klasa implementuje interfejs i jednocześnie go zawiera (dwie linie do tego samego interfejsu: trójkąt i romb).

Kod (Java), iloczyn wektorowy metodą macierzową 
class Vector3DDecorator implements IVector {
    private final IVector srcVector;   // owinięty obiekt
    private final double z;

    Vector3DDecorator(IVector v, double z) { this.srcVector = v; this.z = z; }

    public double[] getComponents() {
        double[] c = srcVector.getComponents();
        return new double[] { c[0], c[1], z };
    }
    public double abs() {
        double[] c = getComponents();
        return Math.sqrt(c[0]*c[0] + c[1]*c[1] + c[2]*c[2]);
    }
    public double cdot(IVector p) {
        double[] a = getComponents(), b = p.getComponents();
        double bz = b.length > 2 ? b[2] : 0;          // wektor 2D ma z = 0
        return a[0]*b[0] + a[1]*b[1] + a[2]*bz;
    }
    public Vector3DDecorator cross(IVector p) {
        double[] a = getComponents(), b = p.getComponents();
        double bz = b.length > 2 ? b[2] : 0;
        double x = a[1]*bz   - a[2]*b[1];
        double y = a[2]*b[0] - a[0]*bz;
        double zz = a[0]*b[1] - a[1]*b[0];
        return new Vector3DDecorator(new Vector2D(x, y), zz);
    }
    public IVector getSrcV() { return srcVector; }
}

Stan behawioralny

Obiekt zmienia zachowanie zależnie od stanu, w którym jest. Z zewnątrz wygląda, jakby zmienił klasę.

Zamiast if (stan == NOWY) ... else if (stan == WYSLANY) ... każdy stan to osobna klasa ze wspólnym interfejsem. Kontekst trzyma bieżący stan i deleguje do niego akcje. Ta sama metoda anuluj() w stanie Nowe zwraca pieniądze, a w stanie Wysłane blokuje operację. Inne przykłady: automat z napojami, automat skończony.

Kod (Java) 
interface StanZamowienia {
    void oplac(Zamowienie z);
    void anuluj(Zamowienie z);
}

class StanNowe implements StanZamowienia {
    public void oplac(Zamowienie z)  { z.zmienStan(new StanWyslane()); }
    public void anuluj(Zamowienie z) { System.out.println("Anulowano, zwrot pieniędzy"); }
}

class StanWyslane implements StanZamowienia {
    public void oplac(Zamowienie z)  { System.out.println("Już opłacone"); }
    public void anuluj(Zamowienie z) { System.out.println("Nie można anulować wysłanego"); }
}

class Zamowienie {
    private StanZamowienia stan = new StanNowe();
    void zmienStan(StanZamowienia s) { stan = s; }
    void oplac()  { stan.oplac(this); }      // delegacja, bez if/switch
    void anuluj() { stan.anuluj(this); }
}

Pamiątka (Memento) behawioralny

Zapisuje migawkę stanu obiektu i pozwala go później przywrócić (Cofnij, zapis gry), nie ujawniając prywatnych pól.

Trzy role: Twórca (obiekt, którego stan zapisujemy; sam tworzy pamiątkę i sam się z niej odtwarza), Pamiątka (niemodyfikowalna migawka), Opiekun (trzyma historię, np. stos, ale nie zagląda do środka).

Pytanie kontrolne: dlaczego Opiekun nie czyta pamiątki? Bo wtedy stan Twórcy wyciekałby na zewnątrz: koniec hermetyzacji.
Kod (Java) 
final class Pamiatka {
    private final String zapisanyTekst;
    Pamiatka(String t) { zapisanyTekst = t; }
    String pobierzTekst() { return zapisanyTekst; }
}

class EdytorTekstu {                       // Twórca
    private String tekst = "";
    void wpisz(String t) { tekst += t; }
    Pamiatka zapisz() { return new Pamiatka(tekst); }
    void przywroc(Pamiatka p) { tekst = p.pobierzTekst(); }
}

class Historia {                           // Opiekun
    private final Deque<Pamiatka> stos = new ArrayDeque<>();
    void dodaj(Pamiatka p) { stos.push(p); }
    Pamiatka cofnij() { return stos.pop(); }
}

// użycie: Ctrl+Z
historia.dodaj(edytor.zapisz());
edytor.wpisz(" coś nowego");
edytor.przywroc(historia.cofnij());

Strategia behawioralny nowe

Rodzina wymiennych algorytmów: każdy w osobnej klasie, wszystkie z tym samym interfejsem.

Klient tworzy obiekt strategii i wiąże go z kontekstem. Gdy klient prosi o akcję, kontekst deleguje ją do strategii. Nowy algorytm to nowa klasa, bez zmian w kontekście.

Kod (Java) 
interface IStrategy { void execute(); }

class NajblizszaJednostka implements IStrategy {
    public void execute() { System.out.println("Wysyłam z najbliższej JRG"); }
}
class KolejnaNajblizsza implements IStrategy {
    public void execute() { System.out.println("Brak wolnych wozów, szukam dalej"); }
}

class Context {
    private IStrategy strategy;
    void setStrategy(IStrategy s) { strategy = s; }
    void execute() { strategy.execute(); }       // delegacja
}

Context c = new Context();
c.setStrategy(new NajblizszaJednostka());
c.execute();

Iterator behawioralny nowe

Sekwencyjny dostęp do elementów kolekcji bez ujawniania jej wewnętrznej struktury.

Kolekcja ma metodę tworzącą iterator. Iterator ma hasNext() (czy są jeszcze elementy) i next() (daj kolejny). Pętla for (x : lista) w Javie to właśnie iterator pod spodem.

Kod (Java) 
interface Iterator  { boolean hasNext(); Object next(); }
interface Aggregate { Iterator iterator(); }

class ListaJednostek implements Aggregate {
    private final Object[] items;
    ListaJednostek(Object[] items) { this.items = items; }
    public Iterator iterator() { return new ListaIterator(this); }   // «create»
    int size() { return items.length; }
    Object get(int i) { return items[i]; }
}

class ListaIterator implements Iterator {
    private final ListaJednostek aggregate;
    private int index = 0;
    ListaIterator(ListaJednostek a) { aggregate = a; }
    public boolean hasNext() { return index < aggregate.size(); }
    public Object next() { return aggregate.get(index++); }
}

Iterator it = lista.iterator();
while (it.hasNext()) System.out.println(it.next());

Obserwator behawioralny nowe

Komunikacja jeden do wielu w formie subskrypcji: podmiot powiadamia wszystkich zapisanych obserwatorów o zmianie stanu.

Podmiot ma kolekcję obserwatorów i metody: dodaj, usuń, powiadom jednego, powiadom wszystkich. Obserwator ma jedną metodę update().

Pułapka w Javie: metody notifyAll() z diagramu nie napiszesz, bo Object.notifyAll() jest finalna. Nazwij ją np. notifyAllObservers().
Kod (Java) 
interface Observer { void update(byte[] data); }

class ObservedSubject {
    private final List<Observer> observers = new ArrayList<>();
    protected byte[] state;

    public void addObserver(Observer o)    { observers.add(o); }
    public void removeObserver(Observer o) { observers.remove(o); }
    public void notifyObserver(Observer o) { o.update(state); }
    public void notifyAllObservers() {
        for (Observer o : observers) o.update(state);
    }
}

class JednostkaJRG implements Observer {
    public void update(byte[] data) { System.out.println("Nowe zgłoszenie"); }
}

8Wektory i układy współrzędnych

Z Lab 2: wektor wodzący zaczyna się w (0, 0). W układzie kartezjańskim zapisujesz go jako (x, y), w biegunowym jako (r, α): długość i kąt od osi OX.

Biegunowy → kartezjański

x = r · cos α
y = r · sin α

Kartezjański → biegunowy

r = √(x² + y²)
α = atan2(y, x)

Ręcznie: α = arctan(y / x) dla x > 0, dla x < 0 dodaj π (180°).

Moduł i iloczyn skalarny nowe

|a| = √(x² + y² + z²)
a · b = x₁x₂ + y₁y₂ + z₁z₂

Wynik iloczynu skalarnego to liczba.

Iloczyn wektorowy nowe

        | i   j   k  |
a × b = | x₁  y₁  z₁ |
        | x₂  y₂  z₂ |

x: y₁z₂ − z₁y₂
y: z₁x₂ − x₁z₂
z: x₁y₂ − y₁x₂

Wynik to wektor prostopadły do a i b. Dla wektorów 2D przyjmij z = 0, wtedy wychodzi (0, 0, x₁y₂ − y₁x₂).

Policz i sprawdź się

Kartezjański → biegunowy

Wpisz x i y, wynik pojawi się tutaj.

Biegunowy → kartezjański

Wpisz r i kąt, wynik pojawi się tutaj.

Iloczyn skalarny i wektorowy

Wpisz składowe obu wektorów (dla 2D zostaw z = 0). Wynik z rozpisanymi krokami pojawi się tutaj.
